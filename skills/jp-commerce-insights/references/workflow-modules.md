# 模块工作流

## SELECTION｜选品与机会

分析需求场景、目标用户、价格带、竞争密度、差异空间、信任门槛、渠道适配、进入成本和风险。输出 `GO / TEST / HOLD / STOP`，并列出判断依据与待验证假设。

不要只用搜索热度判断机会；至少同时考虑用户需求、竞争、产品能力、证据、渠道和商业约束。

## KEYWORD｜关键词

汇总并去重候选词，按以下维度分类：品类词、功能/机制词、场景词、问题/痛点词、比较词、品牌/竞品词、长尾购买词。

标注意图：`DISCOVERY / COMPARISON / VALIDATION / PURCHASE / SUPPORT`。区分有量化数据的关键词与仅有语义相关性的候选词。给出适合Title、Bullet、Gallery、A+、FAQ和广告的位置，但不要堆词。

## COMPETITOR｜竞品

先确认真正竞争框架，再比较产品/变体/Offer、定位与主张、价格与促销快照、Listing故事顺序、Gallery/A+模块角色、Proof与信任元素、评论主题、用户障碍、可防守差异与不可复制部分。

区分“竞品说了什么”“用户如何评价”和“我们是否有证据反击”。

## VOC｜用户评价

完成规范化、去重、产品映射、主题、场景、情绪、严重度、购买驱动、障碍、FAQ与行动分类。保留 `review_id → source_url → 原文 → 洞察 → 行动` 的追溯链。

输出至少包含：样本与覆盖、Top主题、正负向原因、场景、购买前障碍、使用后落差、竞品机会、FAQ/内容机会、产品/营销/客服行动。

## ASSET_CAPTURE｜素材与页面采集

记录可见页面和素材，不把截图本身视为授权资产。至少盘点页面区域与顺序、图片/视频角色、文案主题、证据形式、PC/移动端差异、来源、时间、用途与授权状态。

输出 `SOURCE_FAITHFUL / CREATIVE_REFERENCE / PROOF_REFERENCE / NOT_AUTHORIZED` 分类，供下游内容规划使用。
