# Amazon Page Story Framework

页面级创意先回答消费者决策问题，再决定 Gallery、A+、Brand Story、Series Comparison 与 FAQ 的角色。不要从 Feature 数量反推页面结构。

## 1. Why This Product Exists

先定义：

```text
Consumer Problem
→ Category Trade-off / Existing Alternative
→ Product Answer
→ Hero Promise
→ Proof Pillars
```

要求：

- `Consumer Problem` 是真实用户问题，不是产品 Feature 的反写。
- `Category Trade-off` 说明用户当前为什么需要妥协，例如体积、性能、维护、安装、价格或复杂度。
- `Product Answer` 说明产品如何解决矛盾，不得超出 Product Truth。
- `Hero Promise` 是消费者最终应记住的购买理由。
- `Proof Pillars` 只使用已确认事实、机制、资产和 Approved Claim；未确认项保持 Pending Verification。

## 2. Consumer Decision Questions

完整页面至少检查以下七个问题是否被回答：

1. **What is it?** 产品是什么、属于什么类别。
2. **Why should I care?** 最强购买理由是什么。
3. **Why is it different?** 与用户当前方案相比差异机制是什么。
4. **Can I believe it?** 有什么可见机制、证据、适用边界。
5. **Is it for me?** 适合什么用户、住宅和场景；有哪些限制。
6. **Which one should I buy?** 同品牌产品/Variant 如何选择。
7. **Why this brand?** 为什么相信品牌、产品哲学如何连接品牌。

不是每个问题都必须独占一个模块；但不能因为页面有很多 Feature 就认为问题已经回答。

## 3. Page Unit Roles

| Unit | Primary Job | Avoid |
|---|---|---|
| Gallery | 快速理解、点击后确认购买理由 | 长篇解释、重复所有 Feature |
| A+ | 解释机制、Proof、场景、适配与异议 | 简单把 Gallery 拉成长横幅 |
| Carousel | 需要多步骤、多场景或多 Proof 的展开 | 只做第一张封面 |
| Native Copy | 长文本、可访问内容、条件和细节 | 把所有文字烘焙进图片 |
| Brand Story | 品牌主张、产品哲学、生态与信任 | 重复 Product Hero Copy |
| Series Comparison | 帮助用户选择同品牌产品/Variant | 未批准跨品牌宣传对比 |
| FAQ | 消除购买障碍和使用边界疑问 | 重复规格表 |

## 4. Page Story Spine

先建立 Story Map：

```text
Consumer Question
→ Story Role
→ Main Message
→ Evidence / Proof
→ Page Unit
→ Asset / Native Field
```

再检查：

- Gallery 和 A+ 是否互补；
- Brand Story 是否拥有独立品牌意义；
- Series Comparison 是否帮助选型；
- FAQ 是否处理剩余阻力；
- 同一句 Claim 是否被无意义重复；
- 页面节奏是否从快速理解逐步进入解释和信任。

## 5. Story Rhythm

常见但非固定节奏：

```text
Recognition
→ Hero Promise
→ Differentiation
→ Mechanism / Proof
→ Use Fit
→ Objection Handling
→ Choice Support
→ Brand Trust
```

具体顺序必须服从产品和已批准 Spec。参考页面只能启发 Story Role，不得复制布局或 Trade Dress。

## 6. S30 mini 类产品的适用示例

示例只说明结构，不批准具体 Claim：

```text
日本住宅中的空间限制
→ 小型设备常被认为要牺牲清洁能力 / 强清洁设备往往更占空间
→ Compact body + Roller cleaning + Automation
→ 小さいから置きやすい。でも、掃除まで小さくしない。
→ 尺度 Proof / 清洁机制 Proof / 自动维护 Proof
```

这里的“约28cm”“吸力”“自动维护”等具体数字或能力必须由当前 Product Truth / Approved Claim 决定。

## 7. Review Gate

Page Story Review 至少检查：

- Hero Promise 是否真正来自 Consumer Problem；
- 是否把 Feature 列表错当故事；
- Proof 是否可见、可验证；
- Page Unit 职责是否清楚；
- 是否存在明显重复；
- Brand / Comparison 是否与 Product Story 分层；
- Mobile 下首屏和核心 Proof 是否仍成立。
