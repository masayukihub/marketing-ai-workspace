# 从单张 Brief 到可用成图

用于 PRODUCE、MVP、FULL_FLOW，以及“图片不好看”“太像模板”“与参考不像”等修图任务。它补充现有生产环节，不新增用户入口或人工 Gate。已有 Product Truth、Story、文案、素材批准和精确候选锁继续生效。

## 先判断问题在哪

有旧图时先打开实际文件，同时查看用户认可的参考图、当前 Brief 和上一轮修改要求。不要仅凭提示词评判成图。缺少旧图时可以诊断流程，但不能断言该次生成失败的具体视觉原因。

| 现象 | 先检查 | 最小修复 |
|---|---|---|
| 看完不知道在卖什么 | 购买问题、主信息、画面焦点 | 重写本张 Brief；保留已批准事实 |
| 像 PPT、卡片太多 | 模板是否覆盖选定方向、文字是否替代证明 | 调整本张构图与信息层级 |
| 产品像贴上去的 | 素材机位、接触面、比例、光向、阴影 | 换匹配机位的官方素材或场景；不让 AI 重画产品 |
| “日本家庭”很假 | 空间尺度、材质、生活动作是否具体 | 改场景层；不靠“高级、日系、真实感”堆词 |
| 功能看起来很强但不可信 | 画面中的证据对象和适用条件 | 返回证据/事实环节，停止重复生成 |
| 单张还行，整套重复 | 相邻图的任务、机位、明暗、产品占比 | 只改重复的资产；保持视觉方向 |
| 改一次就全部变了 | 是否沿用原文件、候选 ID、锁定项 | 用局部编辑，保留无关资产的精确文件 |

每次记录：实际观察 → 可能原因 → 受影响资产 → 保留项 → 本轮改动 → 预期能观察到的变化。最多做两轮针对同一问题的修复；仍失败时检查 Brief、素材或制作方式，不无限重抽。

## 制作前写一份具体的 Shot Brief

不是完整研究报告。只为当前 Asset ID 填以下内容：

| 字段 | 要回答的问题 |
|---|---|
| Asset / Placement / Canvas | 哪张图、用在哪里、当前渠道尺寸和手机查看宽度？ |
| Shopper task / Primary message | 用户看完要能做什么判断？只留一个主信息 |
| Desired takeaway / Proof object | 期望记住什么？画面里具体什么东西支持它？ |
| Product sources / Proof sources | 哪个官方 SKU、角度、状态；哪份证据？ |
| Production mode / Evidence mode | 合成、无产品场景生成、证明图、UI 合成、排版；正式证据还是概念示意？ |
| Scene / Camera / Light | 场景中的具体动作、机位、透视、光向与材质 |
| Product placement / Negative space | 主体占比、接触面、留白在哪、哪些区域不能被裁掉？ |
| Copy layer | 已批准日语原文、排版层与文字安全区；不能为了版式删掉必要条件 |
| Neighbor difference | 与前后两张在购买任务或构图上有什么区别？ |
| Must show / Must not show / Locks | 必须看见什么、禁止什么、哪些已批准元素绝不重做？ |

只有在现有 Handoff 缺少这些执行细节时补写；不重新打开已经批准的策略。首次完整图组可先做 2–3 张代表资产验证方向，再按相近制作方式小批推进。默认一张一个候选；只有真实存在两种可行方向时再做一个对照。用户明确要求 9 宫格或其他数量时遵从。

## 选对制作方式

- **SOURCE_COMPOSITE**：官方产品/生活方式素材配合程序化排版。
- **GENERATIVE_SCENE**：图像工具只生成无产品、无 Logo、无文字、无 UI 的场景；产品随后由官方素材合成。
- **PROOF_COMPOSITE**：把已确认机制、测量、适配条件做成图解；无证据时退回上游。
- **UI_COMPOSITE**：真实 UI 截图与官方产品素材合成，不生成相似 UI。
- **DESIGN_LAYOUT**：对已批准内容和来源做排版，不冒充摄影或图像生成。

安装状态、精确接触几何、内部结构等不能通过普通白底产品图推断出来。素材机位不适合场景时，更换场景/请求正确官方素材，不“让模型自然融合”重画产品本体。

## 把 Brief 交给实际制作工具

可用 `scripts/prepare_creative_brief.py brief.json` 校验最小字段并输出分层制作包。它只做字段和来源指针检查，不验证事实、授权或画面，也不调用图像模型。JSON 结构见脚本帮助和合成测试用例。

生成模型只接收当前场景描述、机位、光线、留白、允许的环境参考和禁止项。完整研究、审批状态、Gate、哈希、其他候选、产品规格以及长篇日语文案不进场景 Prompt。产品/证据/UI 来源保留在合成任务中。

场景 Prompt 的写法例如：明确的家庭空间和生活动作 → 与官方素材匹配的机位/透视 → 光源方向与材质 → 为后期主体和文字保留的区域 → 无产品/文字/Logo/UI。禁止只写“高端、专业、日本风、电影感”而没有镜头与空间安排。

Brief 准备好以后必须真的调用当前环境可用的生成/编辑或渲染工具，并记录工具、输入素材、输出文件和当前版本。固定 SVG 卡片渲染属于合成排版；没有场景图就不能声称完成场景生成。工具不可用时保留可执行 Brief 和缺口。

## 审核实际成图，再决定怎么修

打开导出文件，按原尺寸、缩略图和目标手机宽度查看。检查主信息、产品准确性、视觉证明、构图、真实感、品牌适配、手机可读性。写出“看见了什么”，不要从标题复制一个“5 秒理解结果”。没有测量或观察，不填分数。

实际图片审核与自动检查分别记录：

- 自动检查：文件、尺寸、文字长度、来源指针、计划中的版式重复。
- 成图观察：视觉焦点、产品与场景关系、接缝/透视/阴影、真实阅读、与参考的差异。
- 人工选择：用户接受哪一个精确候选。模型审核不代表用户批准。

旧 PDP 兼容层用 [creative-review-record.md](../../amazon-japan-pdp-generator/references/creative-review-record.md) 保存逐项观察和精确文件绑定。其他运行时使用原 Asset Ledger 的等价字段，不建立第二套资产状态。

完成 2–3 张后以及交付前查看 Contact Sheet。记录当前全部 Asset ID 和输出版本；任何图更换后，相应单图和整组观察都要重新确认。局部修复不改变其他已批准文件。实际审美改进只能通过真实成图与用户反馈验证。
